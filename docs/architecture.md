1 系统概述

本系统为基于 RAG + 多模态大模型 API 的医疗辅助问诊平台，仅提供药品科普参考，不可替代执业医师诊断与处方开具。系统采用分层微服务架构，内网保存知识库与原始问诊数据，通过调用国内合规大模型 API 实现图像解析与文本生成，严格做隐私脱敏，规避数据出境风险。

2 整体架构文字描述

整体分为六层，由外到内依次：

接入层：Nginx 反向代理（生产 HTTPS、静态资源）+ FastAPI 网关中间件，统一入口，负责 JWT 鉴权、限流、日志埋点、traceId 生成、跨域处理、熔断前置判断。

应用业务层：FastAPI 业务服务，实现用户会话管理、问诊业务、RAG 检索调用、文件管理、权限校验。

任务调度层：Celery 异步任务队列，搭配 Redis 作为 Broker，处理耗时任务：PDF 文档 OCR 解析、文本清洗、语义切片、向量向量化、向量库入库、定时统计 LLM 用量。

核心能力层：RAG 检索子模块，包含文档预处理、混合检索、重排、隐私脱敏、Prompt 组装。

数据存储层：MySQL、Redis、Qdrant 向量库、本地文件存储。

外部依赖层：调用国内服务商 VL 多模态 API、LLM 文本生成 API，原始敏感数据不会上传外部服务商，调用前自动脱敏。

3 模块划分

3.1 网关中间件模块（FastAPI Gateway Middleware）

职责：统一接口入口、JWT 鉴权、RBAC 权限拦截、QPS 限流、全链路 TraceId 生成、请求日志收集、异常捕获。

边界：不处理业务逻辑，只做流量管控与进入业务路由前的统一拦截（`app/core/gateway.py`）。

3.2 业务服务模块（FastAPI Service）

用户管理子模块：登录、用户信息、角色权限管理

问诊会话子模块：创建会话、多轮追问消息处理（SSE 流式返回）、保存对话记录、查询历史问诊

文件管理子模块：图片 / PDF 文件上传、内网文件存储、文件元数据管理

RAG 调用子模块：接收查询语句，调用检索能力，组装上下文 Prompt

LLM 代理子模块：封装外部 API 调用，隐私脱敏、重试、熔断、多服务商切换

3.3 RAG 检索模块

文档预处理子模块：OCR 识别、文本清洗、章节语义切片

向量子模块：调用 BGE 模型生成文本向量

检索子模块：BM25 关键词检索 + Qdrant 向量检索，RRF 融合打分

重排子模块：bge-reranker-large 对召回结果重排序，过滤无关片段

3.4 异步任务模块（Celery）

文档入库任务：PDF 解析、清洗、切片、向量化、写入 Qdrant

定时任务：每日统计 LLM 调用 token 用量、用量告警检测、向量库快照备份

3.5 存储模块

MySQL：用户、角色、会话记录、文档元信息、审计日志

Redis：Celery 消息队列、接口限流计数器、临时缓存

Qdrant 向量库：存储药品文档切片向量，用于向量检索

文件存储：保存上传 PDF、问诊图片（内网本地存储，不上传外部大模型）

3.6 外部大模型代理模块

封装 VL 图像解析 API、LLM 文本生成 API；内置失败重试、熔断降级、服务商切换、敏感信息脱敏。

边界：仅发送脱敏后的文本，原图、患者隐私原始信息保留在内网。

4 核心业务数据流（问诊场景）

用户前端发起问诊请求（文字描述 + 图片），请求经 Nginx 反代到达 FastAPI 接入层。

接入层中间件校验 JWT、执行限流，生成 traceId，进入业务处理器。

业务服务接收请求，读取图片内网地址，调用 VL 多模态 API（脱敏后），解析图片得到结构化文本。

合并用户文字描述 + 图片解析文本，构造检索 Query，送入 RAG 模块。

RAG 模块执行混合检索 + 重排，返回 TopN 相关药品说明书片段。

业务模块组装系统 Prompt、用户问题、召回参考文档；对 Prompt 上下文做隐私脱敏。

调用外部 LLM 文本 API，获取模型回答；自动追加医疗免责声明。

保存本次问诊会话、参考文档、trace 日志到 MySQL。

结果返回前端展示。

多轮追问数据流（同一会话内二次提问）：

1. 用户在已有会话输入追问，请求到达接入层，进入会话业务处理。
2. 业务服务读取该会话历史消息作为上下文，合并本轮输入构造检索 Query。
3. 执行 RAG 混合检索 + 重排，组装 Prompt（历史对话 + 召回片段 + 本轮问题）。
4. 调用外部 LLM 文本 API，以 SSE 流式增量下发回答片段，前端边收边渲染。
5. 流结束时下发 `done` 事件（含引用文档与免责声明），本轮问答落库。

5 知识库入库数据流（管理员上传 PDF）

管理员上传药品 PDF 文件，请求经过接入层鉴权。

FastAPI 保存文件到内网存储，创建文档元数据记录，创建 Celery 异步任务。

Celery 后台执行任务：PDF/OCR 解析 → 文本清洗 → 语义切片 → BGE 向量化 → 向量写入 Qdrant。

任务状态更新到 MySQL，管理员可查询任务进度。

6 模块调用关系

前端 → Nginx（生产反代） → FastAPI（网关中间件 → 业务路由）

FastAPI 业务服务 ↔ Redis / MySQL

FastAPI 业务服务 → RAG 模块 → Qdrant

FastAPI 业务服务 → Celery（提交异步任务）

Celery 任务进程 → RAG 预处理模块 → Qdrant + MySQL

FastAPI 业务服务 → LLM 代理 SDK → 外部 VL/LLM 服务商 API

7 系统边界说明

内网边界：原始图片、原始问诊记录、完整药品文档，全部保存在内网，不对外网大模型服务商传输。

大模型调用边界：向外传输的仅为脱敏后的文本内容，移除姓名、身份证号、手机号等隐私字段。

业务边界：系统仅做药品知识科普，禁止输出疾病诊断、禁止生成处方。

能力边界：RAG 仅检索本地药品知识库，不允许大模型随意编造信息。

8 部署架构

开发环境

本机直跑业务：FastAPI、Celery worker 直接运行；MySQL、Redis、Qdrant 均为本机服务（3306 / 6379 / 6333），零容器依赖。本地单机部署，用于开发调试。

生产环境（用户规模约 3000）

单机 / 双机 Docker Compose 部署，全部组件单实例运行，不引入 Kubernetes：

服务器：1 台 4C8G（业务服务 + Celery），MySQL / Redis / Qdrant 本机服务同机部署，模型推理机器建议 8G 以上内存

Nginx 反向代理：HTTPS 终止、托管前端静态资源、将 /api/v1 转发至 FastAPI 服务

数据备份：MySQL 每日快照、Qdrant snapshot 备份，备份文件留存内网
监控组件：Prometheus + Grafana 轻量单实例，TraceId 链路日志审计

网络策略：内网隔离，仅反代对外暴露端口；大模型 API 出口仅允许指定出站请求。
